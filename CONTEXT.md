# CoDoc Domain Glossary

Canonical vocabulary for specs, tickets, code, and tests.

## Core Concepts

- **CodeChunk**: An extracted semantic unit from a Python source file (function, async function, class, API endpoint, Pydantic/config schema, or CLI command), identified by a stable `chunk_id` (`module_path::qualified_name`) with line span, signature, docstring, content hash, and raw source.
- **DocSection**: A Markdown documentation slice bounded by heading hierarchy, containing its `section_id`, file path, `heading_path` (e.g., `Configuration > Environment Variables`), line span, raw Markdown content, and extracted `CodeReference` mentions.
- **CodeReference**: A candidate symbol, config key, or CLI command reference extracted from a `DocSection` (backticked identifier, qualified dotted name, or endpoint/CLI pattern).
- **LinkEdge**: A directed relationship between a `DocSection` and a `CodeChunk` in the **LinkGraph**, carrying `link_type` (`heuristic` | `embedding` | `hybrid`), `score`, and `evidence`.
- **LinkGraph**: The persisted JSON mapping between `CodeChunk` and `DocSection` records built during Phase 1, paired with a content-hashed vector index in ChromaDB.
- **CodeDelta**: A paired `(old_chunk, new_chunk)` representation of a changed, added, or deleted `CodeChunk` derived by parsing `base` and `head` revisions of PR-modified files and mapping unified diff hunks to AST spans.
- **ChangeFilterResult**: Output of deterministic AST-normalized filtering on `CodeDelta` items, classifying changes as `meaningful` (signature, decorator, schema, config, or executable body change) or `skipped` (tests, ignored globs, comments, docstrings, whitespace).
- **SuspectSection**: A `DocSection` linked via `LinkGraph` to a meaningful `CodeDelta`, evaluated at the PR `head` revision so same-PR doc updates are respected.
- **StalenessVerdict**: Output of LLM verification on a `SuspectSection`, containing `is_stale` (`bool`), `diagnosis` (specific discrepancy), `change_complexity` (`simple` | `complex`), and `confidence` (`0.0`–`1.0`).
- **RepairPatch**: A targeted Markdown rewrite for a stale `DocSection` generated by the Repair Engine, preserving accurate surrounding prose, style, and structure.
- **ValidationVerdict**: Output of the second-pass LLM quality gate on a `RepairPatch`, checking factual accuracy against `new_chunk`, preservation of accurate content, and style consistency.
- **RepairMode**: Routing decision for a `RepairPatch`: `auto_fix` (applied to a doc-fix PR branch when confidence >= threshold, change is simple, and validation passes) or `review_flag` (posted as a PR comment with diagnosis and suggested draft snippet).
- **RunReport**: Final summary of a CoDoc pipeline execution (`verified_accurate`, `auto_fixed`, `flagged_for_review`, `unlinked_new_symbols`, PR link, and evaluation metrics).
- **EvaluationCase**: A ground-truth benchmark entry (repo revision pair + deliberate doc-breaking change + expected stale `DocSection` IDs) used in Phase 5 to measure TP, FP, FN, precision, recall, and correction quality.
